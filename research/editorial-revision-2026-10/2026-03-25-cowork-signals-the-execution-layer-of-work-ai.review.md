# Coworkの記事の改稿記録

## 問いと論証

対象日2026年3月25日。旧稿と現行の日英本文/metaを通読。
問い: 会議準備を一つの依頼で渡せるようになったとき、資料、分析、説明、予定がつながっていることを誰がどう確かめるか。
判断: Coworkの価値は、複数操作の実行時間だけでなく、人が手でつないでいた作業を引き受けることにある。ただし同じ名称でも参照情報と実行場所は違い、成果物を増やすだけでは判断の根拠が整わない。入力から数値、主張、予定への対応と変更の波及を確認し、人の再調査や修正まで含めて価値を測る。
前日の会話UIから、複数アプリをまたぐ一仕事の整合へ進める。旧稿の調査/実行/管理の役割と広がりを回復し、五社の優劣や業界全体の収束、万能の長時間自律性は回復しない。

| 論点 | 根拠と具体例 | 解釈と限界 |
| --- | --- | --- |
| 手作業でつなぐ仕事 | 想定の顧客会議準備; MSの会議資料/分析/予定例 | 分析や資料の転記を引き受ける意義。想定例とベンダー例を実測にしない |
| 作業場所と情報 | Anth Jan12 VM/local/MCP; MS Mar9 WorkIQ/M365 cloud | 同名で同一権限・同一実行条件としない。どちらが速いとも言わない |
| アプリ間の文脈 | Anth Feb24 Excel/PowerPoint add-in early preview, command forms | 理解の受け渡しと数値/前提の正しさは別。Cowork全接続へ一般化しない |
| 直接接続と画面 | Anth Mar23 connector-first/screen fallback/permission/early limits | 接続がない所へ届くが、操作/確認の増加を価値から引く。後日OS更新は使用しない |
| 役割とつながり | 想定: 読む・分析し説明する・反映する三役 | 必須直列や三エージェントではない。情報から主張と宛先まで追えること |
| 途中の変更 | 想定: 売上の確定値到着後、表/図/資料/メールが旧版のまま | 前提が変わると成果物へ波及。提案と適用を分け、旧版の承認を使い回さない |
| 評価と人 | Anth Jan9 transcript/outcome; Feb24 OpenTelemetry | ファイル/数字/予定の実結果と、人の確認・修正時間。観測機能の有無を完全監査や成功率にしない |
| 価値と試行 | 定型一ファイル処理との比較、会議情報の探索と統合 | すべてにCoworkが有利とはしない。利用者が根拠を確認して次の判断へ進める条件を示す |
