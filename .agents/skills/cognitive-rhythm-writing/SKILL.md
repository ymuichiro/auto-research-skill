# 認知リズムを生むための日本語ライティング規範

内容が正しくても、事実、解釈、限定が同じ長さと調子で続くと、読者は各文の役割を判別しにくい。
この規範は、すでに成立した論証の役割を文の長短と段落の密度に反映し、読者が事実と判断の切替を追えるようにする。

## 併用する規範

作業前に `../japanese-tech-writing/SKILL.md` を読む。
記事や解説文では、先に `../write-concrete-coherent-prose/SKILL.md` で、具体性、前後の論理、根拠と解釈のつながりを確定する。
この規範は最後に適用する。緩急のために主張、例、段落、問いを新しく作らない。

## 基本原理

- 緩急は情報量の増減ではなく、既存の論証にある役割の切替として設計する。事実、比較、解釈、限定がどこで切り替わるかを、文と段落の形で読み取りやすくする。
- 根拠の中に未解決の問い、対立、予想とのずれがある場合は、それを**未回収の緊張**として開いておく。材料がない箇所へ緊張を作らない。
- 答えに至る過程が論証に必要な場合は、考えながら進む声で書く。調査していない迷い、思い込み、告白を演出のために創作しない。
- **生成側の制約**：この規範を適用して文を新しく書くとき、拍・緊張・緩みの材料は状況側（対象世界の出来事・データ・発言、語り手の判断状態）からしか取らない。状況に材料が見つからない位置には、何も足さず平坦なまま残す。本文自身を話題にした文（「〜の列挙はしない」「問いは〜だけである」）でリズムを作るのは、規範の違反であって適用ではない。新造・整形した文は、書いた時点で「緩みと駄文の見分け方」の判定にかける。
- **装置は実現するものであって、宣言するものではない**：この規範に書かれた「緊張」「回収」「拍」などの語を、本文の内容として使わない。「次に問いを置く」「最後に回収する」のように執筆操作を実況せず、事実、問い、答えそのものを書く。
- **場面のない説明文での状況**：物語の場面を持たない解説文では、対象のデータ、計算、トレードオフ、期待と結果の差が材料になる。読者の反応を想像で補わず、本文の進行を語ることで材料不足を隠さない。
- **短文化バイアスの禁止**：拍を作るために文を削るのではない。導入で必要な文脈共有（範囲、観点、比較軸、未確定事項）を削って短くするのは、緩急ではなく欠落である。密度を上げる編集は、共有済み文脈の上でだけ行う。

## 文の拍

- 内容がすでに成立している段落では、短文で足場を打ち、長めの文で流し、短文で止める拍を選べる。拍を作るためだけに文を分割したり、停止文を追加したりしない。
- 断定、不確実性、反論、転回は、根拠と論証にその役割が存在するときだけ文体へ反映する。交互配置や定型の拍を目的に追加しない。
- 短文は、確認できた帰結、比較結果、限定条件など、単独で固定する価値がある内容に使う。読者の視線を止めるためだけの指示文は置かない。

## 段落の密度波形

- 密な段落が続いて読者の判定対象が見えにくい場合だけ、疎の段落を置く。段落数を基準に機械的に挿入しない。疎の段落にも、確定事項の固定、次の判定対象、視点距離の切替のいずれかの新しい役割を持たせる。
- 視点の距離を固定しない。具体（記録、数値、発言、コード）に寄る段落と、意味づけで一段引く段落を交互に置く。
- 箇条書きは、並列関係を散文より正確に示せる場合に使う。列挙後の文は、項目から新しい帰結を導ける場合だけ置き、列挙の言い換えで終わらせない。

## 冒頭の設計

- 冒頭では、記事が答える具体的な問い、根拠にある対立、読者の予想と事実のずれのいずれかを示す。使える型の例：
  - 読者の実感の言い直し（「〜と感じることがあるだろう」）から仮説（「〜が違うのかもしれない」）へ
  - 読者への直接の問いかけ。ただし置き去りにせず、すぐ自分の答えを返す
  - 根拠で検証できる一般命題。あとの本文がその命題を試す
  - 実際に記録された思い込みを肯定的に書き切ってから、事実で崩す場面
  - 前章・前節が残した問いの、当事者の言葉での言い直し
- 予告や要約は、記事の問い、対象、結論の適用範囲を早く理解させる場合に限って置く。書き手の態度や期待感だけを加える文は削除する。
- 読者の反論を先回りする場合は、本文の根拠から実際に生じる誤読を具体的な命題として示す。想像上の抵抗を演出のために作らない。

## 節の入り方

- 節の頭では、直前の節が確定した事実、残した条件、または次に検証する主張を具体的に受け取る。「本節では〜を扱う」という進行説明だけで接続しない。
- 理論、概念、引用は、それが説明する具体的な事実または比較対象と隣接させる。事例と概念のどちらを先に置くかは、読者が前提を理解するために必要な順序で決める。
- 節と節の橋は、前節の帰結と次節の問いの対応が最も明確になる位置に置く。反問、違和感、告白を接続の定型として使わない。

## 列挙の着地

- 性質や分類を列挙したら、各項目がどの事実、実例、判断に対応するかを本文または表で示す。対応づけられない項目は削る。
- 表現の変化より、同じ種類の項目が同じ粒度と構文で比較できることを優先する。

## 問いの回収と結び

- 途中で立てた問いは、根拠がそろった位置で答える。答えを分割するのは、別々の根拠が別々の条件を確定する場合に限り、推進力を作る目的では分割しない。
- 結びは、積んだ抽象を、読者がすでに持っている具体（冒頭の場面、読者自身の経験、序盤の問い）へ着地させてから閉じる。抽象論や一般則のまま終えない。
- 本文で立てた問いには、確認できた答えと未確認の部分を分けて示す。材料不足を読者への委任で埋めず、未解決なら何が不足しているかを具体的に書く。
- 二人称の呼びかけ、読者への依頼（「どうか〜と割り切って読んでほしい」）、書き手の謙抑や断りは、章の冒頭・結びなどの境界でだけ緩みとして機能する。中盤の論証に混ぜない。

## 緩みと駄文の見分け方

判定の軸は一つだけである。
**その文が更新するのは「状況」か、「文書」か。**

- 状況を更新する文：対象世界の出来事・データ・人物の発言、あるいは語り手の判断の状態（思い込み、保留、後悔、譲歩、告白）を新しく伝える。→ 緩みとして残してよい。
- 文書を更新する文：この章・この節・この説明・ここまでの話が「どう見えるか」「次に何を書くか」だけを伝える。→ 原則として削除する。

駄文の典型（いずれも話題が本文自身であり、状況の情報がゼロ）：

- 「ここまでだと、概念の説明に見えるだろう。なので、すぐに例へ戻す。」（説明の見え方と執筆の予定）
- 「要するに、この章の主題は〜ではなく〜である。」（章の性格づけの言い直しだけで、対象の新情報がない）
- 「誤解しないでほしいのだが、〜を否定したいわけではない。」（退ける誤読を特定しない弁明。下の例外1の形なら残せる）
- 「テクニックの列挙はしない。」「〜の話ではない。問いは〜だけである。」（本文の性格・範囲の宣言。否定形でも短文でも、話題が本文自身なら駄文）
- 「先に答えを半分だけ置く。」「最後にもう一度だけ線を引く。」（この規範の装置の実況。装置は内容で実現し、操作を宣言しない）
- 「ここまでで〜は見えた。次の問いは〜である。」「次は〜を見る。」（節末の進行予告。次節は、前節の帰結と次に確かめる具体的な主張を対応づけて始める）

駄文は、長い説明文の形だけでなく、短い断定の形でも現れる。
文書更新の文を削除する代わりに短く断定調へ整形すると、拍が効いた決め台詞に見えて残りやすい。これが駄文の最大の混入経路である。
短くてリズムが良いことは、残す理由にならない。拍の良し悪しは、話題テストを通過した文についてだけ評価する。

良い緩みの典型（いずれも状況か、語り手の判断状態を更新している）：

- 「うまくいっているに違いない。」（思い込み。あとで崩される布石）
- 「まあ、今すぐ手を打つほどでもないのだけど、どこかの時点で整理は要るだろう。」（判断の保留という状態の更新）
- 「最初からわかっていたらそうしていたのに、というのが口惜しい。」（判断の誤差を可視化する感情）
- 「そうしたかった、とは思う。」（反問への譲歩。直後の転回の足場）

文書について述べる文でも、次の四つの形だけは残してよい。

1. **反論処理**：読者の誤読・反論を「」で具体的に書き出して退ける（「ここまでの話を『〜せよ』という主張と読まれると、それは違う」）。退ける対象が具体的に引用されていることが条件。漠然と「誤解しないでほしい」だけの文は駄文。
2. **問いの設置と回答**：記事が答える具体的な問いと、根拠から確認できた答え。本文が「何でないか」「何をしないか」の宣言（「〜の列挙はしない」「〜の話ではない」）は問いの設置ではない。例外1の形で具体的な誤読を退けるのでない限り、削除する。
3. **読者への依頼・断り**：境界に置く「どうか〜と割り切って読んでほしい」。
4. **例の枠の開閉**：架空の例・場面の枠を開く文（「〜としよう」）と閉じる文（「冒頭の例にオチを付けておこう」）。例が架空であることを読者に思い出させ、抽象的な議論から場面へ戻す機能を持つ。境界（節の頭）に置く。話題が本文自身に見えても、例の枠を操作しているなら駄文ではない。

削除と書き換えの手順：

- 文書を更新するだけの文を見つけたら、まず削除して前後を読み、つながるならそれで終わり。
- 削除で論理が飛ぶ場合は、その文が指そうとしていた内容を、状況の側の文に書き換える（「ここまでだと概念の説明に見える」→「この三つの性質は、どれも冒頭の失敗の中にそろっている」）。
- 書き換えた結果の文がまだ本文自身を話題にしているなら（短くしただけ、言い回しを変えただけ）、その書き換えは失敗である。例外1〜3のどれかの形に収まらない限り、文ごと削除して前後を橋渡しし直す。

## 執筆後の点検手順

草稿を書き上げたら、次の順で機械的に点検する。

1. **話題テスト**：段落の頭の文と、独立した短文をすべて拾い、「状況を更新しているか、文書を更新しているか」を判定する。文書側は、例外3形に該当しない限り削除または書き換え。推敲で新しく書いた文・短く割り直した文は、駄文の混入経路なので、書いた直後にもこのテストにかける。
2. **漏出テスト**：この規範の語彙（「緊張」「回収」「拍」等）が執筆操作の説明として本文に現れていないか検索する。現れていれば、その文を削除し、事実または判断そのものを書く。あわせて、節末に「次は〜」型の進行予告がないかを確認する。
3. **問いの対応表**：本文中で立てた問いを列挙し、答えまたは未解決と判断した根拠の位置を指す。対応する材料がない問いは削る。
4. **拍の点検**：長い断定文が連続して読みにくい箇所を探す。既存の事実、比較、留保を使って文を組み替え、内容のない足場、停止、逡巡は挿入しない。
5. **境界の点検**：二人称の呼びかけ・依頼・謙抑が本文中盤にないか確認する。あれば境界へ移すか削る。

## 修正指示への使い方

平坦な文章を診断するときは、症状から処方を引く。

- **全段落が同じ調子で疲れる**：文の拍がない。内容を増やさず、既存の事実、比較、判断の順序と文長を組み替える。
- **正しいのに読み進める気がしない**：記事が答える問いと各節の役割を先に確認する。根拠に未解決の対立がある場合だけ、冒頭で示して回収位置を確認する。
- **理論の節で急に抽象度が上がる**：理論と、それが説明する事実または比較対象が離れている。順序を固定せず、両者を隣接させて対応を明示する。
- **緩い文はあるのに弛んで見える**：緩みが文書更新（進行実況）になっている。話題テストにかけ、状況側の文（感情の微差、判断の保留、思い込み）に書き換える。
- **章末が説教くさい**：抽象論のまま閉じている。読者がすでに持っている具体へ着地させる一文を先頭に置き、未決の問いを一つ残して終える。
- **冒頭が事務的**：態度のない議題表になっている。削るのではなく、予告文に態度を与えるか、予告の前に読者の実感・抵抗の処理を置く。
