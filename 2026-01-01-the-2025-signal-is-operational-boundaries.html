A2Aの移管、Claude Agent SDK、Foundryワークフローを振り返る。接続規格と実行機能が増える中で、成果物の意味や公開条件を誰が決めるのかを整理する。

2025年の発表を、任せる仕事と残る責任から読む

エージェント同士を接続できることと、仕事を最後まで任せられることは同じではない。 接続先が見つかっても、渡す情報、実行を認める操作、結果を確認する担当は決める必要がある。 2025年の発表を振り返ると、これらを実装する道具が、それぞれ異なる形で増えたことが分かる。

本稿では、6月のA2Aの移管、9月のClaude Agent SDK、11月のFoundryワークフローを取り上げる。 年全体の普及率や成功率を測る資料ではない。 接続規格、処理を実行するSDK、処理手順を管理する機能を区別し、どの責任が開発側に残るかを読むための三例である。

接続規格が開かれても、仕事の意味はそろえる必要がある

Googleは2025年6月23日、A2Aの仕様、SDK、開発用ツールをLinux Foundationのプロジェクトへ移すと発表した。 異なるエージェントの能力発見や情報交換を共通化する取り組みを、複数社が参加する運営へ移した出来事である。

この移管だけで、ベンダーの変更が容易になったとは言えない。 例えば「調査完了」という通知を受けても、全対象を調べたのか、一部の資料が取得できなかったのかは、仕事の契約として伝える必要がある。 共通の通信方式と、出力の意味や品質に関する合意は、別に確認したい。

実行用SDKは、調べて作り直す処理を組み立てる

Anthropicの2025年9月29日の説明は、Claude Code SDKをClaude Agent SDKへ改称し、ファイル操作やコマンド実行をコーディング以外へ使う考え方を示した。 情報を集め、処理し、結果を確かめる反復を、調査などへ応用するという説明である。

こうしたSDKは、調査資料を読み、表を作り、計算をやり直す構成を作る手がかりになる。 ただし、紹介された用途が広く定着したという証拠ではない。 どのファイルを読ませるか、生成した計算結果を何と照合するか、どこで処理を終えるかは、用途に合わせて設計する必要がある。

処理手順を保存しても、公開の判断は別に設計する

Microsoftの2025年11月の公開プレビューは、視覚的な編集とYAMLによる処理定義、人が関与するテンプレート、保存時の版管理を紹介した。 実行する処理を図や定義として残し、変更を追える形にする機能である。

ここで、調査記事を作る想定例を考える。 接続規格は別の調査担当へ依頼するために、SDKは資料の取得と下書き作成に、処理定義は確認後に公開へ進む手順の管理に使える。 三つすべてを導入する必要はないが、採用するなら各部分の役割を明らかにしたい。

下書きが完成したことを、公開してよいことと同一視しない。 出典が欠けた場合には差し戻す、確認済みの版だけ公開する、といった条件は作成側で定義する。 2025年の発表から得られる設計上の示唆は、道具の名前をそろえることより、受け渡す成果物と実行を認める条件を具体化することにある。
