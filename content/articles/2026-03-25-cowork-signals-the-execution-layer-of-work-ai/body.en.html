How much work is included in “prepare for the meeting”?

Preparing for a customer meeting might mean reading email, analyzing figures, and drafting a presentation. Adding preparation time to a calendar and sending materials to other people expands the request into changes affecting others. Correcting a draft differs from correcting an invitation or message already delivered.

Anthropic's Cowork and Microsoft's Copilot Cowork provide examples of treating multiple operations as one assignment. Compare what they read, where they leave results, and which changes prompt human review, alongside how long they can work. Those distinctions help define a useful meeting-preparation trial.

Separate “meeting preparation” by who receives its result

Read source material

Reading email, minutes, and spreadsheets to gather issues requires checking which folders and connections are accessible. The result is initially material for the worker; no outside calendar has changed.

Save a draft

After saving slides or a summary, the worker checks the content, location, and version. A created file and correct figures or conclusions are separate things to verify.

Change a calendar or delivery

Moving a calendar time or sending material affects other people. Show who receives what and when, then compare the actual state after approval with the displayed change.

This is not a universal ranking of risk. A draft can contain sensitive information, and a bounded routine calendar change may be pre-authorized. The important point is to specify the affected object and method of review for each operation.

Local file work and deliverables across applications

Anthropic's January 12 release notes introduced Cowork as a research preview in the Claude desktop app, running in an isolated virtual machine with access to local files and MCP integrations. Access to working files distinguishes this setup from simply receiving a written answer.

The February 24 announcement expanded plugins and connectors and also described a research preview passing context between the Excel and PowerPoint add-ins. Turning an analysis into a presentation is a concrete example of work spanning applications. That add-in capability should not be assumed to work identically across every Cowork connection.

For meeting materials, check whether the spreadsheet figures support the claims on the slides. Reducing transcription does not correct a mistaken analytical assumption; it may carry the same error into both files. Producing several deliverables and producing correct content require separate checks.

Copilot Cowork distinguishes preparing files from changing calendars

Microsoft's March 9 announcement describes preparing meeting materials from email, meetings, and files, and separately proposing Outlook calendar changes for approval before applying them. It describes a plan that can be reviewed, changed, or paused. The announced rollout is a research preview for limited customers, with broader Frontier program availability planned for late March.

My interpretation is that these operations need not share one approval boundary. Saving draft materials and changing an appointment require reviewing different objects. In the trial proposed here, prepare the documents first and then review the calendar proposal. The announcement's examples do not establish a measured success rate for a combined task that includes sending messages and changing appointments.

Compare the completion message with the saved result

Once document creation and calendar changes are separated, verify each through its actual result. Anthropic's guide to agent evaluations distinguishes an execution transcript from the resulting environment state: saying that a flight was booked differs from a reservation existing in the database. Likewise, a completion message alone does not verify that meeting materials were saved or appointments updated.

In a trial, open the files, compare their conclusions with the underlying figures, and check that only the approved calendar changes were applied. If the instructions changed midway, also check that an outdated document is not still queued for sending. This is a proposed evaluation, not a measured report of identical behavior in the two products.

Pair each delegated operation with a result to inspect. Separating reading, saving drafts, and changes affecting other people makes it possible to see which steps became easier and which still need review. Compare completed work under defined conditions, rather than treating long execution time as an accomplishment.
