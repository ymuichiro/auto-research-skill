Read the 2025 launches through delegated work and remaining responsibility

Connecting agents does not establish that a job can be delegated end to end. Teams still need to decide what information crosses the connection, which actions are allowed, and who checks the result. Several 2025 announcements supplied different tools for implementing those decisions.

This retrospective examines the June A2A transfer, September Claude Agent SDK announcement, and November Foundry workflow preview. They do not measure annual adoption or success rates. They illustrate distinct responsibilities in communication, execution, and workflow management.

An open communication standard still needs a shared task contract

On June 23, 2025, Google announced the transfer of the A2A specification, SDKs, and developer tools to a Linux Foundation project. The initiative for capability discovery and information exchange between agents moved into a multi-company governance structure.

That transfer alone does not establish easy vendor migration. A notification that research is complete, for example, must distinguish full coverage from completion with unavailable sources. A common communication format and agreement about output meaning and quality require separate attention.

An execution SDK supports repeated research and revision

Anthropic's September 29 announcement renamed the Claude Code SDK to the Claude Agent SDK and described applying file and command tools beyond coding. Gathering information, acting, and checking work formed a reusable loop for activities including research.

This offers a way to build document-reading, table-generation, and calculation workflows. Suggested uses are not evidence of widespread adoption. Developers must still decide which files are accessible, how calculations are checked, and when execution should stop.

Saving a workflow does not define publication approval

Microsoft's November public preview described visual and YAML workflow definitions, human-in-the-loop templates, and versions created on saving. These features make processing steps and changes inspectable.

Consider a hypothetical research-publication workflow. A protocol could carry a request to another researcher; an SDK could retrieve material and prepare a draft; a workflow definition could manage the path from review to publication. A system need not adopt all three, but any adopted component should have a clear responsibility.

A completed draft is not automatically ready to publish. The application must define conditions such as returning drafts with missing sources and publishing only the reviewed version. The design lesson from these announcements is to specify the artifacts being handed over and the conditions permitting action.
