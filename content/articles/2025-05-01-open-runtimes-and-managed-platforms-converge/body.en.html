Choosing a connection and authorizing an action are separate

An agent may be able to call a leave-request API even when the user only wants to check their remaining allowance. Connectivity leaves an important question unanswered: should this operation execute?

AWS's April 2025 implementation article illustrated that distinction with time-off requests. The same month's A2A announcement addressed communication between agents. This article separates that connection mechanism from application-level confirmation.

Return a confirmation or return execution to the application

The April 9 AWS article explains two mechanisms. User confirmation gives the application the proposed function and arguments so it can collect approval before proceeding. Return of control makes the application responsible for execution and permits additional handling, including parameter changes.

The former fits a decision on a presented operation. The latter supports custom editing or processing in the application. Neither means every action requires the same interruption; place confirmation according to the workflow's authorized scope.

User confirmation is not necessarily organizational approval

Confirming the dates in a leave request can differ from a manager approving that request. The AWS user-confirmation mechanism does not establish that an organization's approval process is already implemented.

A proposed application design would display the dates, duration, employee, and operation. Edited dates should become the subject of confirmation. A registered request awaiting review should not be shown as approved leave. These are design recommendations, not claims about every feature of the published sample.

Delegation to another agent does not remove confirmation requirements

Google's A2A announcement described client and remote agents exchanging capabilities, task status, and artifacts. Finding a suitable agent through such a connection does not establish user consent for its action.

Test allowance-only questions, corrected requests, denied execution, and post-execution status separately. Whatever protocol or runtime is chosen, verify that the actual operation matches the content the user authorized. Separating connection and execution responsibility makes that comparison possible.
