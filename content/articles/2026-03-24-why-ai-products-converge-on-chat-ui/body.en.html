Describing an intention and pointing to an edit are different actions

“Make this explanation easier to read” leaves several choices open: length, tone, and structure. Conversation lets a user state the goal and refine it after seeing a proposal. Once the request becomes “shorten only this paragraph,” selecting that paragraph can reduce the need to describe its location in words.

That distinction is useful when designing AI interfaces. My interpretation is that conversation can express goals and exceptions while direct manipulation identifies the object or passage to change. The product announcements below do not establish that chat is the cheapest interface to build or the easiest for every task.

Canvas selects the passage; Pages keeps a shared editing target

Google's Canvas announcement shows highlighting a paragraph and requesting a change in concision or tone. Language describes the change while selection identifies its target. The document remains an editing surface instead of being only another response to read in a conversation.

Microsoft's Copilot Pages announcement describes retaining AI-generated content so people can edit, add to, and share it. The relevant distinction is a common editing target that persists as conversation continues. In a hypothetical team proposal, contributors could collect changes on the same page instead of explaining which response should count as the latest draft.

These are different capabilities: selecting a revision target and retaining a shared document. They are product descriptions, not experiments measuring time savings or error reductions. Test their value on an actual draft by checking whether the intended passage is easy to identify and whether unrelated content changes.

A plan can also become an object of direct editing

Sometimes the desired change concerns upcoming work rather than the document itself. The first version of the Cocoa paper proposes collaboratively creating plans and executing their steps with an agent inside a document editor. In an evaluation with 16 researchers on scientific-research tasks, the authors reported improved agent steerability against a strong chat baseline without sacrificing ease of use.

The result does not establish that a plan interface is better for every user or task. It concerns work with multiple steps that users can inspect and redirect. I take it as a reason to test interfaces exposing the particular unit a user wants to change: a paragraph for writing, or a plan step for research. The appropriate unit depends on the work.

Add an interface where revisions actually happen

A short definition or one-off consultation may work well with answers and corrections in the conversation itself. A separate editor is not automatically necessary. Revising one passage in a long document, jointly updating a draft, or changing an intermediate plan creates a clearer reason to keep the target visible.

A small evaluation task could ask a user to revise one paragraph and hand the latest document to a colleague. Count explanations needed to identify the target, check for changes elsewhere, and verify that the recipient opens the same version. This is a proposed test, not a measured comparison of the products above.

Start with what users need to see and change. That separates work for which a conversation is sufficient from work that benefits from selection, editing, and sharing controls. Judge those additions by whether they make the intended revision and its result easier to verify.
