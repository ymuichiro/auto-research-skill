From writing code to delegating an experiment

Executable code does not finish a machine-learning experiment. Data preparation, method selection, training, and evaluation must connect to an explanation of what improved. Delegating that work requires completion criteria beyond code generation.

MLE-bench and the GPT-5 developer announcement, both available by September 2025, help separate what can be evaluated from what remains to verify. They are not interchangeable rows in one leaderboard.

MLE-bench includes data preparation and training

The first version of MLE-bench uses 75 Kaggle competitions to evaluate work including dataset preparation, model training, and experimentation, with human baselines drawn from public leaderboards. Its task scope differs from writing an individual function.

Improving a competition metric does not establish readiness for a live service. Latency, updating procedures, and data-use conditions need application-specific checks. Reported results also belong to model-and-scaffold combinations, not arbitrary models.

Better tool use still needs an end-to-end experiment test

OpenAI's August 7, 2025 announcement presented GPT-5 coding evaluations and capabilities involving sequences of tool calls. These are relevant ingredients for editing code, receiving execution results, and taking another step.

That announcement does not establish a particular GPT-5 result on MLE-bench. Tasks, environments, and time limits differ. An experiment assistant must be tested as a complete configuration, including its actual data and tools.

Retain both the improvement and the materials to reproduce it

Consider a hypothetical demand forecast using past sales. Before delegation, define the training period, a simple baseline, and the evaluation metric. Keep final evaluation data separate from the data used repeatedly during tuning.

The deliverable should include the data version, executed code, settings, and evaluation results, alongside predictions. Distinguish inability to read the data from successful training with poor accuracy. Reviewers need reproducible materials more than a statement claiming success.

This makes saved work and added review effort visible. The useful decision is whether the agent produced a better result than the baseline in a form that can be checked, beyond merely making the experiment run automatically.
