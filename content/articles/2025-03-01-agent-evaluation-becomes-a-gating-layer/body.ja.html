問い

試作を配備候補として扱う前に、何を評価すればよいのか

AIエージェントの評価を「導入ゲート」と呼ぶとき、評価が配備を自動的に決めるという意味ではない。回答、環境内で変わった最終状態、許可されない副作用、人への引き継ぎを分けて検査し、何を任せられるかを説明できる状態を指す。AgentBench、GAIA、SWE-bench、OSWorld は、異なる仕事が異なる完了条件を持つことを見せた。本稿では、それを一つの総合点にせず、配備判断に必要な検査の組合せとして読む。

回答の契約

必要な根拠を使い、分からない情報を推測で埋めず、利用者に必要な形で返せるか。

実行の契約

初期状態から、許可された操作で、期待する最終状態へ到達したか。

監督の契約

危険な操作を止め、不確実な状態を根拠とともに人へ渡せるか。

ベンチマークが測るもの

「答えられる」と「環境で終えられる」は別の検査になる

GAIA は、推論、マルチモーダル入力、Web 閲覧、道具利用を要する実世界風の質問を置く。初版は466問を用意し、人の回答率と plugin を備えた GPT-4 の比較を報告した。ここで中心になるのは、複数の情報を集めて最終回答を導けるかである。AgentBench も、複数の環境や道具を使うエージェントを評価するため、仕事の種類ごとに成績が異なることを扱った。

SWE-bench は、実際の GitHub issue と対応する pull request をもとに、コードベースを変更して問題を解く課題を作った。OSWorld は、実 Web・デスクトップアプリ、ファイル操作、複数アプリにわたるタスクを、初期状態と実行ベースの評価スクリプトとともに置いた。どちらも、もっともらしい説明ではなく、変更後のリポジトリや画面状態を確かめる。BrowserGym がベンチマークごとの観測・行動空間をそろえようとしたことも、比較には環境の条件が要ることを示す。

これらの数値を自社の配備可否へそのまま転用することはできない。役割は、評価対象を分ける語彙を与えることにある。資料探索の正しさを測るテスト、画面に保存された結果を測るテスト、許されない外部操作を測るテストは、同じ採点器にしない方が失敗を読める。

観測と統制

トレースや確認機能は、平均点の代わりではなく、失敗の説明を支える

Anthropic の computer use は、スクリーンショット観測が短時間の通知を見逃しうること、速度と正確さに制約が残ることを説明した。Operator の発表は、ログイン、支払い情報、CAPTCHA での takeover と、注文・メール送信前の確認を説明した。これらは、画面操作の成功率ではなく、どこで人が介入する設計かを記述する資料である。

AutoGen v0.4 は、非同期メッセージ、event-driven の長期実行、メッセージ追跡、デバッグを備えるとした。Building effective agents は、定めた経路を通す workflow と、モデルが道具の使い方を決める agent を区別する。こうした機能や設計分類は、製品の安全性や有効性を単独で証明しない。それでも、失敗の原因、停止地点、引き継いだ判断を後から確認するための情報を何として残すかを考える材料になる。

評価カード

締切を予定表へ登録するなら、答え・保存状態・操作経路を別に採点する

以下は業務用の評価設計を説明する想定例である。資料には締切日と時刻を、予定表には既存の予定と利用権限を用意する。期待する仕事は、資料から正しい日時を読み、正しい予定表へ一件だけ保存し、必要なら確認を求めることとする。

回答

資料に時刻がないなら勝手に補わず、確認を求める。日時と根拠の箇所を対応付ける。

最終状態

対象の予定表に正しい日時で一件だけ保存されたかを、画面または API の状態で検査する。別の予定表、時刻ずれ、下書き、二重登録は別の失敗にする。

経路と安全性

読み取った資料、使った操作、確認要求、失敗時の状態を記録する。権限がない、または保存結果が未確認なら、人への handoff を正しい結果に含める。

初期データ、予定表の版、許可操作、タイムゾーンが違えば難しさも変わる。改善比較ではそれらの条件を固定し、結果の点数と原因調査用の軌跡を別々に保存する。

配備判断への答え

評価は合否の一数値ではなく、任せる境界を説明するための証拠になる

本稿の「ゲート」は、公開ベンチマークに合格したから配備する、という一段の判定ではない。代表的な仕事について、どの回答を正解とし、どの最終状態を確認し、どの副作用を禁止し、どの状態を人へ渡すかをあらかじめ定めることを指す。そこまで定めれば、試作で生じた失敗を、モデル、道具、環境、採点条件のどこに戻すべきかを議論できる。

最初の配備候補には、代表例を少数に絞り、回答、実行、監督の三契約を別々に検査する。平均点が上がっても、古い代表例で危険な副作用が増えたなら、変更は通さない。このように評価を更新の記録と結び付けることが、派手な試作と監督できる仕事を分ける実務的な境界になる。
