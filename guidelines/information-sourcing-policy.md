# 情報収集ポリシー

## 1. 目的

`Auto Research Digest` は、LLM、AI、AI Agent に関する技術トレンド、実務ユースケース、導入論点を、特定ベンダーの利害から独立して調査し、根拠から導く判断とともに発信する。公開内容の信頼性を担保するため、情報探索、公開根拠、記事としての解釈を明確に分ける。

## 2. 基本方針

1. トピック探索は広く行う。
2. 公開時の根拠は、公式ドキュメントまたは論文として確認できるものに限定する。
3. 公開ページに載せる出典は `publishedSources` に登録したものだけとする。
4. 出典のラベル、URL、種別、必要に応じて公開日を明示する。
5. 新規記事または大幅改稿に進む条件として、対象トピックについて公式ドキュメントまたは論文の URL を 20 件以上収集する。この件数は調査範囲を確保する条件であり、本文で全件に触れる条件ではない。
6. 遡及記事では、記事の日付以前に公開が確認できる一次情報だけを採用する。
7. 通常運用は週 1 本の公開を基本とするが、公開頻度は根拠基準を緩める理由にしない。

## 3. ソース区分

### 採用可能

- ベンダーや標準化団体などの公式ドキュメント
- ベンダー公式ドメイン上で公開された announcement / release / launch / product update ページ
- 論文として公開され、リンクと出典が確認できるもの
- 研究機関・学会・公式リポジトリに紐づく一次情報

### 探索には使えるが、そのまま公開根拠には使わない

- ニュース記事
- 個人ブログ
- SNS 投稿
- カンファレンス現地メモ
- 二次まとめ記事
- 他者が編集した要約ページや解説記事

### 原則として除外

- 出典不明の図表
- リンク切れで原典確認できない情報
- 著者、公開主体、発行時期が不明な資料
- 推測やリークに依拠した未確認情報

## 4. 公開前チェック

公開前に少なくとも以下を満たす。

1. 根拠リンクが生きている。
2. 記事本文の事実主張が `publishedSources` で裏付けられ、複数の根拠から導く解釈は、比較の過程、推論、限界を本文で追跡できる。
3. 公式ドキュメントか論文かを `type` で区別している。
4. 執筆対象の調査インベントリとして、公式ドキュメントまたは論文の URL を 20 件以上確保している。
5. ソースが複数ある場合、それぞれが事実、比較、反証、限界のどれを支えるかが明確である。
6. 実在する実装例と想定シナリオを区別し、想定シナリオを導入事例のように扱っていない。
7. 日付が重要な場合は、本文と出典表示の両方で整合が取れている。
8. 遡及記事では、各 URL が記事の日付以前に公開済みであることを research matrix または調査メモで説明できる。

## 5. 公開ページでの扱い

- 公開ページには、未検証ソースや探索段階のメモを表示しない。
- `publishedSources` 以外の URL は原則として記事末尾の根拠一覧に出さない。
- 本文の事実は一次情報で裏取りする。複数の事実を比較した本稿の解釈は、その推論と限界を示し、事実そのものと混同しない。
- `publishedSources` や「公開根拠」欄には、ニュースサイト、ブログ、キュレーションメディア、転載ページなど第三者著作物の URL を含めない。
- 第三者著作物を探索に利用した場合でも、公開ページには原典の公式ドキュメントまたは論文 URL のみを掲載する。
- 公式 announcement / release / launch ページを根拠として使う場合は、ベンダー自身が公開した一次情報であり、対象日時点に公開済みであることを確認する。

## 6. 1記事あたりの最小基準と週次運用

- 新規記事または大幅改稿を公開候補にする前に、対象トピックの公式ドキュメントまたは論文 URL を 20 件以上収集する。
- 20 件未満しか一次情報が集まっていない場合は、記事化を急がず、調査メモまたは下書きのまま保留する。
- 情報量が多いトピックでは、20件は下限である。ただし、記事本文は件数を消化せず、中心的な判断に必要な資料だけを比較して論点を再構成する。
- 月初スナップショット型の遡及記事でも、各記事ごとに 20 件以上の一次情報インベントリを持つ。
- 週次記事でも 20 件以上の一次情報インベントリを持つことを原則とする。
- 1つの週次テーマだけでは内容が薄い場合は、公開を見送るか焦点を変える。2から4個のシグナルが一つの判断へ収束するときに限りroundupに広げる。
- 週次 roundup にした場合でも、単なる話題列挙にせず、週として何が変わったのかという主論点を 1 本に絞る。
- 週次記事の日付は公開日スナップショットとして扱い、その日以前に公開済みの一次情報だけを採用する。

## 7. 更新時の原則

- 既存記事を更新する場合は、根拠リンクの有効性を再確認する。
- 新しい公式文書や論文が出た場合は、旧来の主張をそのまま温存せず、更新履歴の必要性を判断する。
- 一時的な話題性よりも、検証可能性を優先する。
- 週次運用では、公開本数を優先して薄い記事を出すのではなく、焦点の再設定か公開見送りで品質を守る。
