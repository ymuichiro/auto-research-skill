# Auto Research Digest デザイン適用計画

2026年10月12日に確定したデザインを、サイト全体へ適用する。
最初の見本の透明感、余白、淡い青緑を基準にし、記事の末尾から過去の関連記事へ縦スクロールで読み進める動きを組み合わせる。書体は後の決定に従い、Noto Sans JPへ統一する。
共通CSSとHTML生成を先に変更し、記事ごとの図の追加は内容を確認しながら進める。
ローカル実装と確認は完了した。
確認の範囲と結果は[デザイン改修のローカル確認](design-verification.ja.md)に記録する。

## 確定したデザイン

- 見た目の基準は最初のモバイル見本と初期の本文見本。
- 読み進め方の基準は、過去記事が下から手前へ現れる縦スクロールの見本。
- 背景は淡い青と白を基調にし、探索中の面の重なりに透明感を残す。
- 読んでいる本文は白に近い安定した面に置く。
  本文背面へ反射や光の模様を重ねず、文字の背後に別の記事を透かさない。
- 見出し、本文、操作、補助情報は日本語と英語ともNoto Sans JPへ統一する。
- 青緑はリンク、選択状態、図の関係を示す用途で控えめに使う。
- 過去記事は下の奥から現れ、スクロールに合わせて手前へ近づく。
  本文が読む位置へ来たら変形を止め、通常の縦スクロールにする。
- 本文の視覚的情報は、仕組みの図、比較、根拠のあるグラフで補う。
  図の量を増やすこと自体を目標にしない。

後の見本で試した全面の青い透け模様、強い発光枠、白と原色だけの平板な配色、大きな遠近変形は基準に採用しない。
画像内の文章、図、日付、出典は見本用であり、公開記事へ流用しない。

## 現在の実装と変更対象

サイトはNode.jsで静的HTMLを生成し、Tailwind CSSと共通CSSで見た目を定義している。
日本語と英語の本文は記事ごとのHTMLとして保存されているため、フレームワークを移行せずに適用できる。

| 対象 | 現在の実装 | 変更の役割 |
| --- | --- | --- |
| デザイン規約 | `guidelines/design-system.md` | ダークテーマの規約を今回の決定へ更新 |
| 色、書体、余白、面 | `src/styles/input.css`、`tailwind.config.mjs` | 全ページが使う値と共通部品を整える |
| HTML生成 | `scripts/lib/render.mjs` | 共通シェル、探索、本文、関連導線を変更 |
| テーマと関連記事 | `scripts/lib/topic-hubs.mjs`、関連記事選択処理 | 同じテーマを過去へ辿る順序を生成 |
| ビルド | `scripts/build.mjs` | 記事の読込データと追加スクリプトを出力 |
| ブラウザー処理 | `src/assets/` | 記事読込、奥行き、関連一覧を追加 |
| 記事内容 | `content/articles/*/body.ja.html`、`body.en.html` | 既存の図を整え、必要な図だけ追加 |
| 検証 | `scripts/validate.mjs`とブラウザー確認 | ページ契約、動作、見た目を確認 |

既存のデザイン規約が指定するダークテーマは、今回のユーザー決定で置き換える。
記事の出典、本文の論証、日本語と英語の対応、公開URLの契約は引き続き維持する。

## 画面ごとの適用

| 画面 | 適用する体験 |
| --- | --- |
| トップ | 今読む記事を手前に置き、関連記事を少数だけ奥へ重ねる。全記事への一覧導線も残す |
| 記事一覧とページ送り | 同じ色、書体、カードを使い、全件を探す一覧は読みやすい平面にする |
| テーマ一覧とテーマ詳細 | テーマごとの入口を揃え、詳細では記事の年代のつながりを見せる |
| タイムライン | 日付とテーマを辿れる一覧を保ち、選択した記事を強調する |
| 本文 | 安定した読み物の面、共通の図表、記事末尾から過去記事へ続く流れ |
| 関連の流れ | デスクトップでは補助表示、モバイルでは閉じられる一覧として提供。本文の連続スクロールを主導線にする |
| 出典と編集責任 | 本文より軽い補助情報として揃え、必要な根拠へアクセスできる状態を保つ |
| サイト説明、編集方針、連絡先、各種規約 | 共通シェルと文章スタイルを適用し、長文の読みやすさを揃える |
| サイトマップ、404、フッター | 共通の色、余白、操作状態へ揃える |
| ブラウザー色、アイコン、共有画像 | 公開面と矛盾する色を更新し、既存の画像URLは維持する |

日本語と英語の両方を対象にする。
見本にある検索アイコンなどは、実際に動く導線にだけ使用する。
新しい検索サービスの追加は、このデザイン変更の必須工程には含めない。

## 実装順と完了条件

### 1 基準となる実画面を整える

- 現在のトップ、記事、テーマ、タイムラインをデスクトップとモバイルで記録する。
- デザイン規約を更新し、色、本文幅、書体、余白、面、影、角丸、フォーカス表示を共通の値にする。
- 代表的なトップと記事に、新しい共通シェルと本文スタイルを適用する。
- Noto Sans JPの読みやすさとフォント読込時のレイアウト変化を実画面で確認する。
  行長、文字サイズ、行間を先に整えてから他の画面へ展開する。

完了条件は、最初の見本に近いテイストでトップと本文が表示され、狭い画面でも本文が読みやすいこと。
その時点の実画面を、後工程の比較基準として残す。

### 2 共通部品を全画面へ展開する

- ヘッダー、モバイルナビゲーション、言語切替、フッターを統一する。
- 記事カード、タグ、日付、ボタン、出典行、ページ送りを共通部品として更新する。
- トップ、一覧、テーマ、タイムライン、補助ページへ同じ部品を適用する。
- 既存の比較ブロック、タイムライン、注記、図を青緑の共通スタイルへ揃える。
- 旧テーマの直書き色やSVGの固定色を点検し、残った部分だけを修正する。

完了条件は、全種類のページで配色と操作状態が揃い、古いダーク面が混在しないこと。
共通クラスの変更で吸収できる記事は、本文ソースを個別に変更しない。

### 3 過去記事へ続く縦スクロールを実装する

関連記事選択と本文表示を共通化してから、ブラウザーでの読込と動きを追加する。
静的な記事ページを入口として残し、その上に連続読書の機能を加える。

- テーマ内の記事順をビルド時に生成する。
  同一カテゴリを基本にし、タグの一致を関連性の補助として使う。
  現在記事より古いものへ進み、同じ記事へ戻る循環を作らない。
  同じ調査日の記事は安定した順序で扱い、古い記事と誤表示しない。
  候補がなければ連続読書を終え、他テーマの一覧を案内する。
- 記事単体と連続読書で、タイトル、本文、出典、共有情報を生成する処理を共有する。
  現在はタイトルが共通ヒーロー側にあるため、連続読書用の各記事にもタイトルとメタ情報を含める。
- 記事ごとの軽量な読込データをビルドで出力する。
  本文と必要なメタ情報だけを含め、ページ全体のヘッダー、フッター、スクリプトは重ねない。
  読込データは公開記事と同じ版、同じ言語で生成する。
- 次の記事が近づいた時点で一件ずつ読み込む。
  全記事の事前読込を避け、通信が失敗しても今の本文を残す。
  再試行と記事単体へのリンクを提供する。
- 記事の境目に、日付と過去の関連記事であることを表示する。
  出典と編集責任の詳細は各記事内の開閉できる領域に整理し、根拠にアクセスできる状態を保ちながら次の記事への距離を短くする。
- 奥行きの変化は次の記事の導入面に限定する。
  読む位置へ来たら拡大と変形を止め、本文を安定させる。
  スクロールを強制停止したり、記事ごとに吸着させたりしない。
- 読込前後で位置が飛ばないよう、導入領域と画像の寸法を確保する。
  高速スクロール、上へ戻る操作、画面回転も扱う。
- 追加記事のHTMLに含むID、アンカー、SVG参照は記事ごとに衝突を避ける。
  既存の記事単体URLとアンカーは維持する。
- 読んでいる記事の共有、言語切替、タイトル表示を追従させる。
  ブラウザー履歴は記事が読む位置へ入ったときだけ更新し、スクロールごとに履歴を増やさない。
  戻る、進む、再読込で記事と読む位置を復元する方針を、実装の初めに固定する。
- canonical、hreflang、構造化データは記事単体の契約を維持する。
  表示中の記事に合わせてURLを更新する場合は、ページメタ情報も同じ記事へ揃える。
- JavaScriptが動かない場合も元の記事全文と関連記事リンクを読めるようにする。
  動きを減らす設定では、奥行きの演出を省き、記事が縦に続く構造を残す。

完了条件は、今の記事から過去記事へスクロールで読み進め、上へ戻れること。
読込失敗、重複読込、遅れた応答、履歴復元、共有対象の切替で、読んでいる記事を失わないことも確認する。

### 4 探索と関連一覧をつなぐ

- トップの少数の記事に奥行きを付け、手前の記事を主な入口にする。
- モバイルでは奥の記事を小さなタップ対象にせず、一覧と通常のリンクからも選べるようにする。
- 関連一覧を連続読書と同じテーマ順から生成し、読んでいる記事を示す。
- モバイルの関連一覧には閉じる操作、フォーカス管理、戻り先を用意する。
- 探索から本文へ移る際の表示を揃え、直接URLを開いた場合も同じ本文へ到達させる。

完了条件は、探索、本文、関連一覧で記事のタイトル、日付、順序が一致すること。
キーボードとタッチの両方で記事を選び、本文へ戻れることを確認する。

### 5 内容に合う図を追加する

デザインの全画面適用と、記事ごとの編集作業を分ける。
共通部品の整備だけで全記事へ新しい見た目を適用できる状態を先に完成させる。

- 仕組みの図、前後の比較、根拠のあるグラフ、研究の時系列を共通部品として用意する。
- 文章中心の記事、比較が多い記事、図を持つ記事を代表として選び、部品が使えることを確認する。
- 新しい図は一記事ずつ、日本語と英語の内容を確認して追加する。
  図だけで論証を置き換えず、対象、条件、出典、限界を本文と対応させる。
- HTMLまたはSVGで実装し、スマートフォンで一列に並べても意味が伝わるようにする。
- 色だけで関係を示さず、ラベルと代替説明を付ける。
  本文と図の連動は、この対応が成立する箇所に限定する。

完了条件は、代表記事で図が内容の理解を助け、日本語と英語で同じ意味を保つこと。
全記事への図の追加は別のチェックリストで進捗を管理し、共通デザインの完了と混同しない。

### 6 全画面の検証と公開準備

- `pnpm build`に含まれる検証と`git diff --check`を実行する。
- 日本語と英語で、トップ、一覧、テーマ詳細、タイムライン、本文、出典、補助ページ、404を確認する。
- 代表幅は360px、390px、768px、1440pxとし、文字拡大、横向き、長い英語タイトルも確認する。
- SafariとChromium系ブラウザーで、スクロール、透過、フォーカス、履歴、共有を確認する。
  モバイル幅での確認と実機確認は別に記録する。
- コントラスト、タップ領域、キーボード操作、モーダルのフォーカス、動きを減らす設定を確認する。
- フォントと画像の読込時の位置ずれ、連続読書の通信量、描画負荷、記事を追加した際のDOM増加を確認する。
  全面のぼかしや毎フレームの重いDOM計測は避ける。
- 新しい動作のテストは、記事の重複追加、遅れた応答、再試行、テーマ末尾、ID衝突、戻る操作、共有対象の誤りに絞る。
  CSSの値やカード数を写すだけのテストを増やさない。
- ローカル検証の結果と残った確認項目を添えて、差分と実画面を提示する。
  公開後は`pnpm verify:public`で生成物との一致を確認する。
  ローカル完了、実機確認、公開反映を別々に報告する。

## 実装と公開の手順

実装は次の単位で差分と確認結果を残す。
代表画面を整えた後は共通部品で横展開し、ページごとの調整を繰り返す量を減らす。

- デザイン規約と代表画面を整える。
- 共通部品を全ページへ展開する。
- 同テーマの過去記事を選び、縦スクロール、履歴復元、共有、読込失敗からの再試行を実装する。
- 探索画面と関連一覧をつなぎ、既存図表と代表記事の視覚情報を整える。
- 日本語と英語の全画面を検証し、公開準備を整える。
- mainへ反映した後、公開ワークフローと公開生成物の検証結果を確認する。

既存の`research/`と`output/`には未追跡ファイルがあるため、実装用の差分へ無関係な調査結果や画像を混ぜない。
最初の見本と縦スクロール見本をレビュー基準とし、画像の好みを毎工程で再定義せず、実画面の読みやすさと操作を調整する。
